# Headshot

Character headshots on examine. Players set an image URL with the Add headshot button under the description in
the profile editor; Preview has the server fetch it and shows it exactly as examiners will see it. When the
character spawns, the server fetches the image once, scales it to fit 256x256 and re-encodes it as PNG. Anyone
who examines the character within details range while their face is visible, by the same rule that shows their
name instead of "Unknown", sees it inline in the examine tooltip as a
128px thumbnail that smoothly grows to full size while hovered (`HeadshotPortrait`).

Clients never contact the image host: the server downloads it and relays the PNG. Downloads only connect to public
addresses (checked at connect time, so redirects and DNS rebinding can't reach the server's own network), are
capped in size and time, and must be https. The image hash stays server-side until a face is visible, so a client
can't match hashes to unmask someone. A client may only download a hash it was just shown.

Entry points: `HeadshotSystem` (server: spawn, examine, image and preview requests, the admin Remove headshot
verb), `HeadshotFetcher` (download, address filter, re-encode), `HeadshotRules` (URL checks shared by client and
server), the client `HeadshotSystem` (tooltip portrait and texture cache) and `HeadshotWindow` (editor).

Admin: the Remove headshot verb clears a live character's headshot; spawns are logged with the URL under the
Identity log type. CVars: `wf.headshot.enabled`, `wf.headshot.allowed_hosts` (comma-separated, subdomains
included; empty allows any public host) and `wf.headshot.max_download_kb`.
