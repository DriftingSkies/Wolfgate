# PdaStorage

Software distribution and storage for the PDA. The **App Store** cartridge is preinstalled on every PDA and lists
`pdaApp` catalogue entries with category and search filters, sizes, access and compatibility flags, a simulated
download with a progress bar, and install/uninstall. The **Storage** tab shows the 128 GQ drive, installed programs
with removal and copy-to-disk, inserted cartridge media, and an inserted data disk with copy-to-PDA.

A program is still an ordinary cartridge entity with `CartridgeComponent` and `UIFragmentComponent`; installation
spawns the program prototype into the loader's `program-container`, exactly as cartridges already did. Storage is
therefore the container plus a capacity in GQ (`CartridgeLoaderComponent.StorageCapacity`), and used space is derived
from `CartridgeComponent.Size` so it can never disagree with the contents. Preinstalled firmware and readonly system
apps are exempt from the 128 GQ user capacity; disks count everything they hold.

Data disks (`PdaDataDisk`, advanced, super - 32/64/128 GQ) store programs in their own `data` container, so contents
travel with the disk item and survive ejection and save/load. A disk can declare `startingPrograms`; the contractor
loadout uses this to ship one preloaded disk instead of several loose cartridges. The PDA has a dedicated disk slot
(`PDA-disk`) and a header eject button. Cartridges are treated as single-app removable media: inserting one exposes
its program in the storage tab for a local copy.

Removal policy: preinstalled programs are marked as system apps and do not consume the 128 GQ user capacity.
Redownloadable apps (news, crew list, art catalogue, market, game hub, net probe, log probe, lattice status, ...) can
be removed and downloaded again; core apps (notepad, ColoTalk, the store itself) and role tools that are not sold in
the store (wanted list, bench/judge line) carry `readonly` and stay locked. Store listings never point at a readonly
program, so a download can always be uninstalled to refund its space.
Media handling: installing from a cartridge consumes only disposable media, and only the cartridge that was installed
from. Store downloads and disk copies never touch the cartridge slot. The store fragment keeps its live UI across
repeated setup calls, so progress and storage updates continue to reach the visible screen.

Entry points: `PdaStoreSystem` (catalogue, timed downloads, install/uninstall/copy), `DataDiskSystem` (disk containers
and examine text), `PdaStoreInstallerSystem` (store on every PDA), `ProgramStorage` (size/used/duplicate maths),
`PdaStoreUi` + `PdaStoreUiFragment` (XAML, built on the Part 1 `PdaUi` controls), and the `pdaApp` / `pdaAppCategory`
prototypes in `Resources/Prototypes/_WG/PdaStorage`.
