# PixelShift

SS13-style pixel shifting. Hold **Pixel shift** (`WGPixelShift`) and tap movement keys to nudge your own sprite a pixel
at a time; hold **Tilt sprite** (`WGPixelTilt`) and tap left or right to lean it 5 degrees at a time. Holding a movement
key keeps going straight from the press, with no wait after the first step, and the sprite glides as it moves. **Reset
pixel shift and tilt** (`WGPixelShiftReset`) puts it back, and so does taking a step (a movement key pressed with
neither key held, while the mob can move; turning in place doesn't count). All three start unbound and sit under
Movement on the Controls tab. The SS13 preset puts shift on B and tilt on V; B is also Resist there, and the shift
binding gets a higher priority so both fire.

How fast a held key moves the sprite is each player's own choice, in the box beside the shift and tilt keys on the
Controls tab (`KeyRebindTab.PixelShift.cs`). They are client cvars the server reads per player:
`wg.pixel_shift_speed` (20 px/s, 1 to 100) and `wg.pixel_tilt_speed` (100 degrees/s, 5 to 360), double the old
fixed repeat of 1 px or 5 degrees every 0.1 s.

Pressing either key stops a walking mob, and it stays stopped after the key is let go until a movement key is pressed
again, like the turn-in-place key. Ghosts and anything else without a mob state ignore the keys and keep moving.

Limits are server cvars: `wg.pixel_shift_max_offset` (16 px per axis, half a tile) and `wg.pixel_shift_max_tilt`
(45 degrees). Lowering one pulls existing shifts back inside it. Restrained, stunned, critical, dead or asleep mobs
can't adjust it (`ActionBlockerSystem.CanInteract`), and holding a key still keeps them from walking.

`WGPixelShiftComponent` holds the shift and is networked, so everyone sees it. The server adds it on the first tap;
`SharedMoverController.WgTryPixelShift`, from a marked edit in `HandleDirChange`, hands key presses to
`WGPixelShiftSystem.TryNudge`, or to `ResetOnWalk` when no key is held, and key releases to `ReleaseDirection`. The
press is the first step; `WGPixelShiftSystem.Update` then builds up the player's speed each server tick and moves the
shift a whole pixel or degree at a time.

On the client `WGPixelShiftVisualsSystem` glides the shown shift and tilt toward the set ones each frame (trailing by
1/20 s at any speed), so a held key, a nudge, a reset or a step eases rather than snaps, and adds them to the sprite
after animations run; `WGPixelShiftRestoreSystem` takes them off before the next frame, the same pattern as Waddle, so
lunges, jitter and the lying-down rotation still play from the mob's own base. The tilt always stacks on whatever
rotation that base has, so a mob lying down or buckled can tilt too. Whatever sets the rotation between frames (the
rotate animation, `LayingDownSystem` turning a lying mob) becomes the new base and the tilt goes back on top, so
standing up always ends upright plus the tilt. Only the body moves: `StatusIconOverlay` (marked edit) and the xeno HUD
overlays draw from `WGPixelShiftVisualsSystem.UnshiftedOffset`, and a marked edit in `JitteringSystem` keeps the shift
out of the base offset jitter returns to. Sprite layers such as the typing indicator still move with the body.
